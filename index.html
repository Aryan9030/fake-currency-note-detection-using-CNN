The model

univariate LSTM · many-to-many
01 Sliding window last T normalised hours
02 LSTM cells gates carry memory across T
03 Dense head ht → ŷt+1
04 Denormalise back to kilowatts
forget gate ft = σ(Wf·[ht−1, xt] + bf)
input gate it = σ(Wi·[ht−1, xt] + bi)
candidate gt = tanh(Wg·[ht−1, xt] + bg)
cell update ct = ft ⊙ ct−1 + it ⊙ gt
output gate ot = σ(Wo·[ht−1, xt] + bo)
hidden state ht = ot ⊙ tanh(ct)
prediction ŷt+1 = Wy·ht + by
objective L = ½T−1 Σ (ŷt+1 − yt+1)²

Why an LSTM here?

Load is dominated by periodic structure — a daily double peak, a weekly weekday/weekend split, and slow weather drift. The cell state ct acts as a differentiable memory that can hold “where in the day are we” across the whole look-back window, which a plain feed-forward net cannot do without explicit calendar features.

What is actually running

Every gate pre-activation is computed in a hand-written loop over Float64Arrays. Gradients are accumulated by backpropagation through time over the full window, clipped to a global norm of 5, and applied with Adam. Nothing is mocked — the loss you see fall is real.

Honest caveats

The series is synthetic, so it is a teaching instrument rather than a grid oracle. Recursive multi-step forecasts compound error, which is exactly why the band widens with the horizon. Swap generateLoad() for your own CSV and the rest of the pipeline is unchanged.
